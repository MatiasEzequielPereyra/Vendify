## Root cause and correction for the 10 reported failures

1. **Products:** verifier expected the retired `openEditor(producto)` call shape. The typed controller receives the product through the current typed adapter and delegates with its declared `ProductsController` parameter type. Updated the assertion to verify typed parameter/delegation structure.
2. **Cash:** checks assumed legacy Spanish `mantener`, event-target and untyped state APIs. Updated assertions to follow typed `keep`, `selectRegister(id)`, and the current cash-state owner/API.
3. **Branches:** verifier required a `const branchAdministrationController` declaration. Runtime composes typed controllers via `let` plus assignment. Updated source and bundle checks around actual typed APIs without collapsing owner boundaries.
4. **Active branch:** same stale `const` assumption. Assertions now follow typed composition and verify active-branch ownership remains separate.
5. **Commercial/platform:** checks expected legacy const names and retired lifecycle hooks. Updated to typed owners, the actual `run` lifecycle and observability setup callback, retaining commercial/platform separation.
6. **Sales:** old matcher expected a single-line `registerSale` signature/call. The offline callback is injected and called inside the real offline branch across multiline code. Checks now verify composition and consumer invocation from source.
7. **Offline:** serializer, parser and migration functions live in `src/products/products-offline-cache.ts`; they are injected through `productsApi` into `application-offline-storage.ts`. The old check looked in the wrong module. Now both implementation and injection path are checked; none of these checks were removed.
8. **Navigation events:** exact string matching did not tolerate formatting/CRLF. Replaced with structural source matching that checks the real keydown listener, one call, typed handler ownership and ordering relative to `armBackGuard` and `popstate`.
9. **Observability:** verifier inspected removed `setupStabilityV23011`. It now verifies the typed diagnostics owner, lifecycle/setup and no duplicate diagnostics ownership in the overlay.
10. **Modular HTML:** verifier unconditionally tried to read a nonexistent modular `dist-refactor-modular/app.js`. It now distinguishes legacy/staging from modular targets: legacy/staging retain their bootstrap controls, while modular checks assert typed entry, no `app.js`, DOM/fragments, html-loader and bootstrap order.

Three negative contract tests exercise detection of missing delegation, duplicate ownership, and a returned `app.js`. Shared helpers are in `scripts/refactor-verifier-contracts.mjs`.
